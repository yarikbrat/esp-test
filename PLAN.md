# План работ: стенд ESP32 + UART TO ETH (B) + HC-SR04 + BMP585/BMP581

Источник требований: `tz/ТЗ_Embedded_ESP32_DevKit_FreeRTOS_NVS_v2.docx`. Бюджет по ТЗ: 16–24 ч.

## 0. Что выяснено о модуле UART TO ETH (B) (по мануалу Waveshare)

- Ядро ZLAN (утилита Vircom, протокол Realcom, файл param.txt). UART 3.3 V TTL, до 460800 бод (на wiki указано до 115200, нужно проверить).
- Заводской IP **192.168.1.254**, static, маска 255.255.255.0, шлюз 192.168.1.1. Пин DEF к GND >1 с → возврат к заводским настройкам.
- **Собственный веб-конфигуратор модуля по умолчанию на порту 80**, но этот порт настраивается («Web access port 1–65535»).
  → План: перенести веб модуля на 8000, порт TCP Server поставить 80, чтобы адрес `http://192.168.144.36/` работал без 8080.
- TCP Server принимает **до 30 соединений** одновременно, а UART у него один. Отсюда **предположение, которое надо проверить
  на железе:** данные из всех соединений сливаются в один поток, а ответ с UART уходит во все соединения. В любом случае
  ESP32 не видит границ соединений и не может закрыть TCP. **Это главный архитектурный риск** (см. §3).
- Пины-индикаторы: `LINK2`=0 — кабель подключён; `LINK`=0 — есть TCP-соединение; `RST` (активный 0); `DEF`.
- Пишут, что есть «AT-команды по UART для чтения и записи параметров», но синтаксиса нет ни в мануале Waveshare,
  ни в мануале ZLAN. **Без них ESP32 не сможет сам поменять IP модуля** (п. 3 ТЗ). Нужно запросить у Waveshare/ZLAN
  (support@zlmcu.com) документ «serial AT command» для своей ревизии модуля.

## 1. Решения, которые фиксируем сейчас

| Вопрос | Решение | Почему |
|---|---|---|
| Фреймворк | ESP-IDF v5.x (CMake, `idf.py`) | нативные FreeRTOS, NVS, `esp_partition`, драйверы I²C/UART/RMT; ТЗ отдельно оценивает FreeRTOS |
| HTTP | свой минимальный HTTP/1.1-сервер поверх UART-потока | `esp_http_server` работает только с сокетами, а у нас только UART |
| Два барометра | **две отдельные шины I²C** (I2C0 и I2C1) | у BMP581 и BMP585 одинаковые адреса 0x46/0x47; если один датчик повиснет и зажмёт SDA, второй продолжит работать. Запасной вариант: одна шина, адреса 0x46/0x47 через SDO |
| Различение датчиков | регистр CHIP_ID (BMP581=0x50, BMP585=0x51, сверить с datasheet) | ловит перепутанную разводку |
| HC-SR04 | 5 V питание, ECHO через делитель 1k/2k на вход ESP32; замер через RMT RX или ISR + `esp_timer`, таймаут ~30 мс | ESP32 не терпит 5 V на входах |
| Настройки | NVS: структура с версией и CRC32, отдельный ключ на каждый канал p₀ | битая или пустая запись → значения по умолчанию |
| История | свой кольцевой журнал на отдельном разделе raw flash (`esp_partition`), записи фиксированного размера с seq и CRC | см. §4 |

## 2. Предварительная распиновка (уточнить по присланным платам)

|---|---|---|
| GPIO17 (U2TX) | модуль RXD | |
| GPIO16 (U2RX) | модуль TXD | |

## 3. HTTP через «прозрачный» UART: как не сломаться

Модуль склеивает все TCP-соединения в один поток, поэтому сервер строим под это:
- Отвечаем строго по одному запросу в порядке поступления, всегда с `Content-Length`. Держим keep-alive, потому что ESP закрыть соединение не может.
- Вся страница — **один** файл (HTML+CSS+JS inline, gzip), `<link rel="icon" href="data:,">`, чтобы браузер не открывал лишних соединений.
- JS опрашивает `/api/state` раз в 1 с, держит не больше одного запроса в полёте, при таймауте повторяет.
- Парсер — конечный автомат: лимит заголовков (~2 KB) и тела (~512 B), таймаут незавершённого запроса (~2 с), ресинхронизация по `\r\n\r\n` после мусора и сброс по фронту LINK.
- Проверить на железе: две вкладки, F5 подряд, обрыв кабеля посреди ответа. Если модуль это позволяет, ограничить число соединений до 1–2.
- Если ответы во все соединения ломают вторую вкладку, задокументировать «одна вкладка» как ограничение.

## 4. Журнал истории во flash

- Раздел `histlog` 256 KB = 64 сектора по 4 KB. Запись ~32 B: seq, session_id, t_since_boot_s, p1, h1, flags1, p2, h2, flags2, crc.
  Около 8000 записей, при интервале 10 с это ~22 ч.
- NOR-flash дописывается в стёртую область без стирания, изнашивает только erase. Один сектор стирается раз за полный круг кольца,
  то есть износ равномерный по построению. Пишем каждую запись сразу из задачи логгера. При внезапном отключении теряется
  не больше одной текущей записи (≤ 1 интервал).
- На старте сканируем первую запись каждого сектора, находим максимальный seq. Битый хвост (CRC) пропускаем.
- `session_id` — счётчик загрузок в NVS. «Тестовый лимит» — уменьшенный размер кольца через Kconfig или через API для проверки перезаписи.
- В UI: заполнение, число записей, счётчик ошибок записи, последние N записей с постраничной выдачей.

## 5. Задачи FreeRTOS (черновик)

| Задача | Приоритет | Период | Что делает |
|---|---|---|---|
| `sonar` | 5 | 60–100 мс | HC-SR04, медиана из 5 |
| `baro` ×2 (или одна на обе шины) | 5 | 50 мс (20 Гц) | чтение, IIR-фильтр, калибровка нуля |
| `net_rx` | 4 | по событию UART | парсер HTTP, формирование ответа |
| `logger` | 2 | интервал журнала | снимок двух каналов, запись во flash |
| `settings` | 2 | по очереди команд | запись в NVS (не блокирует веб) |

Обмен: снимок состояния под mutex с короткой критической секцией (копирование структуры), команды (zero, reset zero,
настройки) через очереди. Калибровка — флаг в задаче барометра; повторное нажатие во время калибровки возвращает «занят».
Стеки подбираем по `uxTaskGetStackHighWaterMark`, отчёт выводим в лог.

## 6. Что можно сделать до прихода плат

1. **Окружение:** поставить ESP-IDF v5.x в WSL, собрать пустой проект, сделать таблицу разделов (nvs, app, histlog). Проверить проброс USB в WSL (`usbipd`).
2. **Чистая логика на C с тестами на хосте** (gcc + Unity, без железа):
   - формула высоты и 3 эталонных расчёта для протокола (p=p₀ → 0; p<p₀ → «+»; p>p₀ → «−»);
   - автомат калибровки нуля (≥10 валидных за ≤3 с, иначе ошибка с сохранением старого p₀, защита от повторного запуска);
   - валидация IP, маски и шлюза (непрерывная маска, шлюз в подсети, запрет сетевого и broadcast-адреса);
   - HTTP-парсер: частичные пакеты, мусор, переполнение, таймаут;
   - кольцевой журнал поверх эмулятора flash в RAM: переполнение, обрыв записи, битый CRC, восстановление после «перезагрузки»;
   - сериализация настроек с версией и CRC.
3. **Хост-эмулятор стенда:** тот же HTTP-код, где UART заменён TCP-сокетом, плюс фейковые датчики. Открываем в браузере
   и гоняем UI через Playwright, проверяем поведение одного потока без закрытия соединений.
4. **Веб-интерфейс:** одна страница, три блока, история, сеть; состояния «Немає даних», «застаріло», «Нуль не встановлено», «Калібрування», «Нуль відновлено з пам'яті».
5. **Документы:** каркасы README, ARCHITECTURE и TEST_PROTOCOL (таблица из §8 ТЗ с пустыми ячейками фактов), схема подключения.
6. **Запросы и покупки:** AT-команды модуля у Waveshare/ZLAN; резисторы 1k/2k для делителя, 4.7k для подтяжек, провода, макетка,
   рулетка, USB-TTL адаптер (настраивать модуль с ПК без ESP), патч-корд. На ПК статический IP 192.168.144.x. Vircom ставится на Windows-хост.

## 7. Порядок работ, когда придут платы

1. Осмотр: точные модели и ревизии, маркировка ядра модуля, есть ли на платах датчиков подтяжки и стабилизатор, перемычки SDO, HC-SR04 или HC-SR04P (3.3 V).
2. Модуль отдельно: USB-TTL + Vircom. Режим TCP Server, порт 80, веб модуля на 8000, IP 192.168.144.36, 115200 8N1.
   Проверить echo через TCP, AT-режим, поведение двух соединений. **Записать всё в README.**
3. ESP32 + модуль: эхо, затем реальный HTTP-сервер со страницей-заглушкой.
4. Датчики по одному: I²C scan и CHIP_ID на каждой шине, затем HC-SR04 на 20/50/100 см.
5. Сборка всего: задачи FreeRTOS, NVS, журнал.
6. Отказы: снять ECHO, отключить один барометр, выдернуть кабель, затем вернуть всё и убедиться, что работа восстанавливается без перезагрузки.
7. Прогон 30 мин, протокол, фото, видео.

## 8. Открытые вопросы и риски

- **Подтверждено на эмуляторе:** если клиентов на общем потоке два (две вкладки или вкладка плюс скрипт), куски их
  запросов перемешиваются, а ответы получают оба. Сервер на ESP32 это исправить не может. Проверить на модуле первым
  делом. Варианты: ограничить модуль одним TCP-соединением (если Vircom позволяет) или задокументировать «одна вкладка».

- **AT-команды модуля** — без них смену IP придётся делать через Vircom вручную. Это нарушает требование ТЗ, и тогда это нужно честно указать в ограничениях.
- Ведёт ли себя модуль при нескольких соединениях так, как описано в §3. Проверяется только на железе.
- Какие именно breakout-платы BMP585/BMP581 приедут: напряжение, подтяжки, адреса.
- Дедлайн: по ТЗ он согласуется перед стартом.
