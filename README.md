# Стенд ESP32: HC-SR04, BMP585, BMP581 через Ethernet

Прошивка ESP32 DevKit і локальний вебінтерфейс: відстань із HC-SR04, тиск і відносна висота з двох незалежних
барометрів BMP585 і BMP581, обнулення кожного барометра, журнал історії у flash, зміна мережевих налаштувань.
Доступ лише через дротовий Ethernet (модуль Waveshare UART TO ETH (B)), без інтернету і без CDN.

- Архітектура, задачі FreeRTOS, формати збереження: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)
- Протокол перевірок за розділом 8 ТЗ: [`docs/TEST_PROTOCOL.md`](docs/TEST_PROTOCOL.md)
- Робочі нотатки під час збирання (російською): `docs/cheatsheet.md` — шпаргалка команд, `docs/hardware-log.md` — журнал, `docs/connections.md` — фактичне
  підключення, `docs/wiring.md` — пояснення схеми, `docs/uart-to-eth-b.md` — дослідження модуля,
  `docs/network-access.md` — доступ із різних комп'ютерів, `docs/photos/` — фото.

## 1. Обладнання і підключення

| Плата | Що робить |
|---|---|
| ESP32 DevKit, модуль ESP32-WROOM-32, USB-C (CH340) | прошивка, HTTP, датчики, NVS, журнал |
| Waveshare UART TO ETH (B), прошивка модуля V1.452 | TCP Server на порту 80 ↔ UART2 ESP32, прозора передача |
| BMP585 (I2C0) і BMP581 (I2C1), плати з власними підтяжками I2C і стабілізатором | тиск |
| HC-SR04 | відстань |

### Схема

| ESP32 | Куди | Призначення |
|---|---|---|
| `VIN` (5 В від USB) | модуль `5V`, HC-SR04 `VCC` | живлення 5 В |
| `3V3` | BMP585 `VCC`, BMP581 `VCC` | живлення 3.3 В |
| `GND` | `GND` усіх плат | спільна земля |
| `D17` (UART2 TX) | модуль `RXD` | ESP32 → мережа |
| `D16` (UART2 RX) | модуль `TXD` | мережа → ESP32 |
| `D25` | модуль `RST` | перезапуск модуля (активний 0), прошивка тримає його відпущеним |
| `D21` / `D22` | BMP585 `SDA` / `SCL` | шина I2C0, адреса 0x47, CHIP_ID 0x51 |
| `D18` / `D19` | BMP581 `SDA` / `SCL` | шина I2C1, адреса 0x47, CHIP_ID 0x50 |
| `D33` | HC-SR04 `Trig` | імпульс 10 мкс |
| `D32` | HC-SR04 `Echo` через дільник 1 кОм / 2 кОм | `Echo` 5 В → близько 3.3 В на вході ESP32 |
| `BOOT` (GPIO0) | кнопка на платі | утримання 5 с повертає початкові мережеві налаштування в ESP32 |

- Сигнали модуля UART TO ETH (B) — 3.3 В, узгодження рівнів не потрібне.
- Барометри мають однакову адресу, тому кожен на своїй шині I2C: так ESP32 їх розрізняє, а зависання одного
  датчика не блокує інший. Прошивка перевіряє CHIP_ID і помічає переплутані датчики.
- `DEF` модуля (заводське скидання) не підключено: див. «Відомі обмеження».
- Модуль можна живити й від `3.3V`, але 5 В беремо з `VIN`, щоб не навантажувати стабілізатор ESP32.

## 2. Інструменти і версії

- ESP-IDF **v5.5.6** (CMake, `idf.py`), ціль `esp32`. Сторонніх бібліотек немає: драйвери BMP58x і HC-SR04,
  HTTP-сервер і журнал написані в проєкті. Регістри BMP58x — за Bosch BMP5_SensorAPI.
- Для тестів на ПК: `gcc`, `make`, `python3`. Збирання перевірене в WSL2 (Ubuntu 24.04), прошивання — через
  `usbipd-win` 5.3.0.

## 3. Збирання і прошивання

```sh
. ~/esp/esp-idf/export.sh
idf.py build
idf.py -p /dev/ttyUSB0 -b 460800 flash monitor
```

Готовий образ після збирання: `build/baro_stand.bin`, таблиця розділів `partitions.csv`
(`nvs` 24 КБ, `factory` 1.5 МБ, `histlog` 256 КБ).

Тести ядра на ПК (з AddressSanitizer і UBSan) та емулятор стенда:

```sh
make -C host test          # 5429 перевірок
make -C host emu && ./host/build/emu --port 8080   # http://127.0.0.1:8080/
```

Емулятор запускає те саме ядро (парсер HTTP, API, обнулення, журнал), а TCP-частина повторює поведінку модуля:
усі з'єднання зливаються в один потік, відповідь іде всім. Команди в stdin: `baro0|baro1|sonar on|off`,
`lift <м>`, `dist <см>`, `noise <Па>`.

`tools/bringup/` — тестова прошивка першого запуску (HTTP через модуль, сканування I2C, сирі показання).

## 4. Мережа і UART

| Параметр | Значення |
|---|---|
| Адреса за замовчуванням | **192.168.144.36**, маска 255.255.255.0, шлюз не задано, DHCP вимкнено |
| Сторінка | **http://192.168.144.36/** (порт 80) |
| Конфігуратор модуля | http://192.168.144.36:8000/ (пароль порожній) |
| Режим модуля | TCP Server, прозора передача, протокол None, No-Data-Restart вимкнено |
| UART | UART2 ESP32, **115200 бод, 8N1**, без керування потоком |

Щоб відкрити стенд, комп'ютеру потрібна адреса з мережі `192.168.144.x`, наприклад `192.168.144.10/24`, на тому
мережевому порту, куди підключено стенд. Інші підключення комп'ютера (Wi-Fi, інтернет) це не зачіпає. Покроково для
Windows, Linux і macOS: `docs/network-access.md`.

### Первинне налаштування UART TO ETH (B)

Модуль із заводу: 192.168.1.254, порт даних 80, конфігуратор теж на 80, 115200 8N1.

1. Живлення модуля від `VIN`/`GND` ESP32, кабель Ethernet у ПК, ПК — адреса `192.168.1.10/24`.
2. http://192.168.1.254 → пароль порожній → Login.
3. **Крок 1:** Device IP `192.168.144.36`, Device Port `4196`, Device Web Port `8000`, Gateway `0.0.0.0` → Submit.
4. ПК — адреса `192.168.144.10/24`, http://192.168.144.36:8000 → Login.
5. **Крок 2:** Device Port `80` → Submit.

Порт даних 80 не можна задати в тій самій формі, де конфігуратор переїжджає з порту 80: модуль відповідає
«Success!», але нічого не зберігає (перевірено дослідами, `docs/uart-to-eth-b.md`). Налаштування модуль застосовує
одразу, перезапуск не потрібен, після вимкнення живлення вони зберігаються.

### Зміна IP через вебінтерфейс

1. ESP32 перевіряє формат і допустимість (суцільна маска /8–/30, адреса не мережа і не broadcast, не 0.x, 127.x,
   169.254.x, не multicast, шлюз у підмережі). Невалідне введення відхиляється, робочі налаштування не змінюються.
2. Валідні параметри стають «очікуваними», а сторінка сама надсилає їх у конфігуратор модуля (вхід і форма
   `ok.html` на порту 8000; модуль переходить на нову адресу одразу).
3. Сторінка перевіряє, що стенд відповідає за новою адресою, і відкриває її.
4. Сторінка, відкрита за новою адресою, надсилає `POST /api/net/commit`. ESP32 приймає його, лише якщо запит
   прийшов саме на нову адресу (заголовок `Host`): це доводить, що модуль переїхав. Тоді параметри записуються
   в NVS як активні, і після вимкнення живлення відновлюється саме ця конфігурація. Якщо змінено лише маску або
   шлюз, `commit` надсилає та сама сторінка одразу після форми модуля.
5. Очікувані параметри теж зберігаються в NVS (ключ `netp`): якщо ESP32 перезапуститься, поки сторінку за
   новою адресою ще не відкрито, підтвердження все одно спрацює. Звичайні запити (опитування стану) зміну не
   підтверджують.
6. Поки зміна очікує, сторінка показує її з кнопками «Підтвердити» і «Скасувати» (`/api/net/cancel`): так
   зміну маски чи шлюзу, підтвердження якої загубилося, можна завершити або відкликати вручну. Нову IP можна
   підтвердити лише зі сторінки, відкритої за цією IP. «Скасувати» відкликає зміну лише в ESP32: якщо модуль уже
   отримав нові налаштування, їх треба повернути в його конфігураторі (порт 8000).

ESP32 не має власного мережевого інтерфейсу і не може змінити адресу модуля по UART: формат службових команд
модуля виробник не публікує. Тому адресу модуля змінює браузер, але сторінка й команди працюють лише через
Ethernet на адресі стенда, без зовнішнього сервера.

### Повернення до початкової адреси

1. Знайти модуль: програма виробника VirCom (Windows, без встановлення:
   https://files.waveshare.com/upload/4/42/VirCom_en.rar) або перебір адрес і `arp -a` (MAC модуля `28-80-e4-…`).
2. Перевести ПК у мережу знайденої адреси, відкрити `http://<адреса>:8000`, задати Device IP `192.168.144.36`,
   маску `255.255.255.0`, Gateway `0.0.0.0`.
3. Утримувати `BOOT` на ESP32 5 с: ESP32 теж повертає в NVS початкові налаштування.

Якщо модуль скинуто до заводських (`DEF` на `GND` понад 1 с) — первинне налаштування вище.

## 5. Датчики, фільтрація і налаштування

| Датчик | Налаштування | Опитування | Фільтрація |
|---|---|---|---|
| BMP585, BMP581 | normal mode, ODR 25 Гц, тиск ×8, температура ×1, глибокий сон вимкнено | 20 Гц | ковзне середнє тиску за 1 с (20 вимірювань); межі правдоподібності 30–125 кПа |
| HC-SR04 | `Trig` 10 мкс, фронти `Echo` у перериванні GPIO | кожні 100 мс (ТЗ: ≥ 60 мс) | медіана 5 останніх; діапазон 2–400 см; `Echo` чекаємо не довше циклу |

- Висота: Δh = 44330 × (1 − (p / p₀)^0.1903) м. p₀ — середнє щонайменше 10 нових валідних вимірювань за 1–3 с
  після натискання «Встановити нуль»; якщо за 3 с їх замало, нуль не змінюється і показується помилка.
- Ковзне середнє зменшило шум на нерухомому стенді з ±9 см до ±4 см (1σ). Атмосферний дрейф воно не прибирає:
  зміна погоди дає 4–8 м «висоти» на годину, протяг — швидкі стрибки. Перед вимірюванням нуль варто ставити
  заново (ТЗ, розділ 6).
- Помилки: 3 помилки читання поспіль → повторна ініціалізація датчика, далі спроба раз на секунду. Помилка
  одного каналу не зупиняє інші.

## 6. Внутрішня пам'ять

- **NVS** (простір `stand`): `net`, `netp`, `log`, `zero0`, `zero1`, `boot`. Кожен запис має magic, версію і CRC32;
  відсутній або пошкоджений запис → значення за замовчуванням. Пишеться лише після підтвердженої зміни
  (обнулення, скидання нуля, налаштування журналу, нова адреса) і один раз при старті (лічильник сесій).
- **Журнал історії**: розділ `histlog` 256 КБ (64 сектори по 4 КБ), запис 32 байти, **8192 записи**; гарантовано
  доступні щонайменше 8064 (кільце стирає найстаріший сектор цілком). Політика заповнення — кільцевий запис із
  видаленням найстаріших даних. При інтервалі 10 с це близько 22 год історії.
- Кожен запис пишеться у flash одразу, без буфера в RAM: запис у стертий flash не зношує його, а сектор стирається
  один раз за прохід кільця (рівномірне зношування). При раптовому вимкненні втрачається щонайбільше запис,
  що саме пишеться. Детально: `docs/ARCHITECTURE.md`.

## 7. Відомі обмеження

- **Кілька клієнтів одночасно.** Модуль зливає всі TCP-з'єднання в один потік UART і надсилає кожну відповідь
  усім з'єднанням. Одна сторінка працює стабільно (400 запитів поспіль без помилок). Якщо стенд відкрито в
  різних браузерах або на різних комп'ютерах, відповіді змішуються: сторінка розпізнає чужі відповіді за
  `X-Req-Id`, рахує відкриті сторінки за `X-Client-Id` і показує попередження. Вкладка, що відкривається в цей
  момент, може отримати замість сторінки чужу відповідь (JSON) — допомагає оновлення (F5).
- **Адресу модуля змінює браузер**, а не ESP32 (див. розділ 4). Якщо нова адреса з іншої мережі, ніж комп'ютер,
  сторінка попередить, що адреса не відповідає; ESP32 збереже її як активну лише після першого запиту за нею.
- **`BOOT` повертає налаштування лише в ESP32.** Адресу модуля треба повернути в його конфігураторі (розділ 4).
  Автоматичне заводське скидання модуля через `DEF` не підключене: без зовнішньої підтяжки 10 кОм цей вивід під
  час прошивання ESP32 не має визначеного рівня.
- **LINK/LINK2 модуля не підключені**: сторінка не показує окремо стан кабелю; втрату зв'язку видно за віком даних.
- **Календарного часу немає**: у журналі — номер сесії і секунди від її початку.
