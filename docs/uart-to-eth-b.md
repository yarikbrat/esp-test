# UART TO ETH (B): що відомо про модуль

Дослідження модуля Waveshare UART TO ETH (B), перевірене на стенді 2026-10-24. Знадобиться, якщо доведеться
переналаштовувати модуль або змінювати прошивку. Як налаштувати модуль крок за кроком — README, розділ 4.

Модуль побудований на ядрі ZLAN (утиліта VirCom, протокол Realcom), прошивка модуля V1.452, MAC 28-80-E4-96-1E-BE.

## Заводські налаштування

- Після скидання через `DEF` (низький рівень довше 1 с): IP **192.168.1.254**, маска 255.255.255.0, шлюз
  192.168.1.1, порт даних 80, вебконфігуратор теж на порту 80, пароль порожній.
- Модуль прийшов з адресою 192.168.1.200 і портом даних 4196 — це були чиїсь попередні налаштування.
- TCP Server тримає до 30 з'єднань одночасно.

## Налаштування для стенда

TCP Server, статична адреса 192.168.144.36/24, шлюз 0.0.0.0 (порожній), порт даних **80**, вебконфігуратор на
**8000**, UART 115200 8N1 без керування потоком, протокол None (прозора передача), перезапуск без даних вимкнено.

## Форма вебконфігуратора

Джерело: https://www.waveshare.com/w/upload/a/aa/Waveshare_web_uart_to_eth_b.zip

- **Вхід:** `POST /ip_en.html`, поле `lgk` (пароль, типово порожній). Cookie немає, сесію тримає модуль.
- **Збереження:** `POST /ok.html` з усіма полями форми. Модуль відповідає «Success!» і посиланням на нову адресу.

| Поле | Значення | Варіанти |
|---|---|---|
| `dvn` | назва пристрою, до 9 символів | |
| `lca` | IP | |
| `lcp` | порт TCP (даних) | для стенда 80 |
| `wbp` | порт вебконфігуратора | для стенда 8000 |
| `lcm` | маска | |
| `lcg` | шлюз | порожній = `0.0.0.0` |
| `wkm` | режим | 0 TCP Server, 1 TCP Client, 2 UDP, 3 UDP Group |
| `ipm` | режим IP | 0 Static, 1 DHCP |
| `bdr` | швидкість | 0 1200 … 9 57600, A 76800, B 115200 |
| `dtb` | біти даних | 0 = 8, 1 = 7, 2 = 6, 3 = 5 |
| `prt` | парність | 0 None, 1 Odd, 2 Even, 3 Mark, 4 Space |
| `stb` | стоп-біти | 0 = 1, 1 = 2 |
| `flc` | керування потоком | 0 None, 1 CTS/RTS, 2 DSR/DTR, 3 XON/XOFF |
| `dsa`, `dsp` | адреса і порт призначення | для режиму клієнта |
| `ndr`, `nrt` | перезапуск без даних: увімк./вимк. і час | **тримати вимкненим**, інакше модуль сам перезапуститься, якщо довго немає запитів |
| `rct` | час перепідключення | |
| `ptc` | протокол | 0 None (прозорий), 1 Modbus TCP to RTU |
| `rto` | тайм-аут команди | |
| `emh` | призначення не з'ясоване | 0 No, 1 Yes |
| `rcg` | інтервал конфлікту RS485 | |
| `nwk`, `rtp` | новий пароль і повтор | |

Прошивка формує цю форму в `components/core/src/uart_eth.c`, а сторінка надсилає її модулю під час зміни IP.

## Перевірено на стенді

- **Налаштування застосовуються одразу**, без перезапуску, і переживають вимкнення живлення.
- **Пастка з портами:** якщо новий порт даних (`lcp`) дорівнює **поточному** порту вебконфігуратора (`wbp`), модуль
  відповідає «Success!», але не зберігає жодного поля. Зворотний випадок (новий `wbp` дорівнює поточному `lcp`)
  працює. Тому із заводських налаштувань — у два кроки: спочатку `wbp=8000` (можна разом з адресою), потім окремою
  формою `lcp=80`. Перевірено дослідами:

  | Було (`lcp`/`wbp`) | Надіслали (`lcp`/`wbp`) | Результат |
  |---|---|---|
  | 4196 / 80 | 80 / 8000 | не збереглося (кілька спроб: curl і браузер, одразу й через хвилини після входу) |
  | 4196 / 80 | 4196 / 8000 | збереглося |
  | 4196 / 8000 | 80 / 8000 | збереглося |
  | 80 / 8000 | 4196 / 80 | збереглося |
  | 4196 / 80 | 81 / 8000 | збереглося |

- **Поки на `DEF` низький рівень**, модуль відповідає «Success!», але нічого не зберігає і скидається до заводських.
- **Кілька клієнтів:** запити всіх TCP-з'єднань надходять в UART одним потоком, а кожну відповідь ESP32 модуль
  розсилає в усі відкриті з'єднання (перевірено двома одночасними `curl`). Дві вкладки одного браузера зазвичай
  ідуть одним з'єднанням і не заважають; різні браузери чи комп'ютери отримують відповіді одне одного. Сторінка
  розпізнає це за `X-Req-Id` і попереджає.
- **Службові байти:** після застосування налаштувань модуль пише в UART 32 двійкові байти
  (`00 ff 00 ff 00 00 00 fe 00 fe 00 00 ff 00 00 40 ff 00 00 a0 fd 01 00 00 08 a9 ff 02 00 00 00 00`). Парсер ESP32
  пропускає байти, з яких не може починатися запит.
- **Знайти модуль з невідомою адресою:** дати мережевому порту ПК адресу в потрібній мережі, пропінгувати всі адреси
  (`for /L %i in (1,1,254) do @start /b ping -n 1 -w 300 192.168.1.%i >nul` у `cmd`) і подивитися `arp -a`; модуль
  впізнається за MAC `28-80-e4-…`. Або програмою VirCom (кнопка Search).

## Що не перевірено

- Послідовні команди налаштування через UART: у документації ZLAN згадані (10-байтовий преамбульний код), але опис
  формату публічно не знайдено. Тому ESP32 сама модуль не переналаштовує.
- Рівні виводів LNK і LNK2 (бічні, не припаяні).
- Чи знаходить VirCom модуль, коли комп'ютер в іншій підмережі.
