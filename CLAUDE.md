# CLAUDE.md

Інструкції для Claude Code у цьому репозиторії. Що робить стенд і як його зібрати — README.md; архітектура —
docs/ARCHITECTURE.md; результати перевірок — docs/TEST_PROTOCOL.md; поведінка модуля Ethernet — docs/uart-to-eth-b.md;
схема підключення — docs/wiring.pdf.

## Власник і спілкування

- Власник проєкту — новачок в електроніці й C. Пояснювати просто, з аналогіями, без жаргону; залізо — покроково.
- У чаті відповідати **російською**. Документація, коментарі в коді й тексти вебінтерфейсу — **українською**.
- Великі зміни — спочатку коротко пояснити план; апаратні дії — лише покроково й з перевіркою.

## Безпека заліза (найважливіше)

- Будь-які зміни дротів — **лише без живлення** (USB вийнято). Перед увімкненням — перевірка (фото, мультиметр).
- **Перед кожною прошивкою** звірити `main/board.h` з фактичним підключенням (docs/wiring.pdf): якщо прошивка робить
  вивід **виходом**, на ньому не повинно бути нічого, крім пристрою, яким він керує. Історія: дріт DEF модуля стояв на D33
  замість D26, нова прошивка зробила D33 виходом із 0 — модуль скинувся до заводських налаштувань.
- Виводи впізнавати за підписами на платі, а не рахуючи позиції.
- Вхід ESP32 — до 3.6 В; сигнали 5 В — лише через дільник або перетворювач рівнів.

## Команди

```sh
. ~/esp/esp-idf/export.sh                 # ESP-IDF v5.5.6 у кожному новому терміналі
idf.py build
idf.py -p /dev/ttyUSB0 -b 460800 flash    # зберігає налаштування в NVS
idf.py -p /dev/ttyUSB0 monitor            # лог (вихід Ctrl+])
make -C host test                         # тести ядра на ПК з ASan/UBSan, мають бути 0 failures
make -C host emu && ./host/build/emu --port 8080   # емулятор стенда: http://127.0.0.1:8080/
./tools/make-release.sh                   # оновити firmware/ після будь-якої зміни коду
```

- `firmware/baro_stand_full.bin` (адреса 0x0) **стирає NVS** — нулі, IP, журналювання. Для оновлення без втрати
  налаштувань — три окремі файли або `idf.py flash`.
- WSL: плата підключається через usbipd-win (`usbipd attach --wsl --busid <id>` у Windows, потім
  `chmod a+rw /dev/ttyUSB0` від root). BUSID свій на кожному комп'ютері (`usbipd list`).
- WSL може не бачити мережу стенда; тоді запити йдуть через Windows: `/mnt/c/Windows/System32/curl.exe http://192.168.144.36/api/state`.
- Відкриття послідовного порту (pyserial, monitor) перезапускає плату — попереджати власника.

## Стенд і мережа

- Стенд: http://192.168.144.36/ (порт 80), конфігуратор модуля — http://192.168.144.36:8000/ (пароль порожній).
- ПК у мережі стенда: 192.168.144.10/24, шлюз не потрібен.
- Модуль розсилає кожну відповідь усім TCP-з'єднанням: під час перевірок через curl на сторінці можуть з'являтися
  чужі відповіді, і навпаки. Для перевірок — одна вкладка або закрита сторінка.
- Барометри дрейфують метрами за годину через погоду: перед вимірюванням висоти обнуляти обидва.

## Правила коду

- `components/core/` — логіка без ESP-IDF (збирається й на ПК, покрита тестами в `host/tests`); `main/` — залізо,
  драйвери, задачі FreeRTOS. Нову логіку класти в core і покривати тестами.
- Без динамічного виділення пам'яті в робочому циклі; буфери фіксованого розміру.
- Блокування: `g_app.lock` — спільний стан, `g_app.log_lock` — журнал. Порядок: спершу `log_lock`, потім `lock`;
  ніколи не чекати `log_lock`, тримаючи `lock`. Довгі дії (flash, формування відповіді) — без замка, за копією.
- Коментарі українською, короткі, однорядкові. Виняток: `/* fallthrough */` лишається англійською (його читає GCC).
- Усі тексти, які бачить користувач (сторінка, повідомлення API), — українською.
- Після змін: `make -C host test`, `idf.py build`, перевірка в емуляторі або на стенді, потім `./tools/make-release.sh`.
